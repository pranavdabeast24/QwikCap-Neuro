# Work on QwikCap

Agree on the work, confidentiality, code rights, and allowed use with the maintainer before contributing.
A pull request does not transfer ownership by itself.
Check any employer or institution rights too.

Use a branch and a private pull request.
Explain what changes for the user and how you checked it.
Keep each change small.
Follow [developer setup](docs/GETTING_STARTED.md) and [the handoff](docs/HANDOFF.md).

Write in plain English inspired by ASD-STE100.
Use short sentences and consistent names.
Put one instruction in each sentence.
Use the actual button and menu labels.
Keep build details and historical evidence out of first-use instructions.
We do not claim formal STE compliance.

Use fictional records for tests.
Keep real patient data, credentials, local projects, and private screenshots out of GitHub.
The named synthetic packets and example workbooks in [FIXTURES.md](FIXTURES.md) are approved exceptions.

Keep required third-party notices with customer builds.
Read [licensing](docs/LICENSING.md), [source permissions](OWNERSHIP.md), and [data limits](SECURITY.md) before sharing a pilot.
